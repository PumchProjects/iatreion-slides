# iatreion-slides

Generate spreadsheets from configured experiment logs.

## Requirements

- Python 3.12+ with `xlsxwriter`
- SSH and `rsync` access to the configured remote host; `rsync` 3.x is recommended for aggregate progress

## Configuration

Create the local configuration before running the pipeline:

```bash
cp config.example.toml config.toml
```

Edit `config.toml` to define the remote host, downloads, logical experiment units, collection settings, spreadsheet output, labels, and report metadata. Download and unit roots are project-relative; other relative paths are also resolved from the project root.

Each model in a unit selects a download by ID. Its logical model ID is `name + suffix`, where `suffix` is optional. This allows repeated source models to coexist in one unit while `model_map` provides their display labels.

## Pipeline

Run the following commands from the project root.

### 1. Download logs

```bash
scripts/extract.sh
```

Every download is written to its configured local root. The script excludes large or unnecessary training artifacts. Use `--dry-run` to inspect transfer statistics without writing files. Disable the proxy to ensure successful downloads.

### 2. Merge logical units

```bash
python -m scripts.merge
```

This builds every unit root from relative symbolic links to its configured downloads. Re-running the command safely replaces roots previously generated by this tool. Collection outputs written through these links are stored in the download directories.

### 3. Collect derived results

```bash
python -m scripts.collect
```

For each unit, this processes the configured validation stages. Internal validation aggregates feature importance and training fusion weights; external validation extracts final evaluation text, modality weights, and ranked rules.

### 4. Export the spreadsheet

```bash
python -m scripts.to_excel
```

The configured metrics from every unit are written to the single workbook at `excel.output`.

## Deprecated Typst report

The files in `report/` are retained as historical reference. They still assume the pre-cohort result layout and are not maintained or validated by this pipeline.
